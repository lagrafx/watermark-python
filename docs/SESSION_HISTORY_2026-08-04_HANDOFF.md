## Current App Behavior
- Auth: Microsoft Graph app-only auth, including certificate/PFX support.
- GCC High support: set `CLOUD_ENV=gcch`.
- Target site/library config comes from `.env`.
- Libraries are selected by `SP_LIBRARY_NAMES`.
- Per-library watermark PNG paths are set with `SP_LIBRARY_WATERMARKS`.
- Every targeted library must have an explicit watermark mapping; otherwise the app fails fast.
- It supports subfolders in targeted libraries.
- Current supported file types:
  - `.docx`, `.docm`
  - `.xlsx`, `.xlsm`
  - `.pptx`, `.pptm`
  - `.pdf`

## State And Delta Behavior
- State is JSON, not SQLite.
- State tracks:
  - last successful run timestamp
  - processed item IDs
  - Graph delta links per drive/library
- Delta tokens are used per SharePoint drive/library, not per subfolder.
- The goal is to avoid scanning/reprocessing every file every run.
- The app skips already-watermarked IDs when processing delta changes.
- Dry run does not update state.
- Deleting the state file forces a fresh baseline/reprocess behavior; the app recreates it on a successful non-dry run.

## Metadata Work
- Customer asked about metadata-driven watermarking and include/exclude subfolder rules.
- We have not implemented metadata rules yet.
- We added `--list-fields` so admins can discover SharePoint internal field names before rule design.
- Use:
  - source: `python -m watermark_app --list-fields --log-level INFO`
  - portable: `.\watermark-app.exe --list-fields --log-level INFO`
- Output includes:
  - `field=` internal SharePoint field name
  - `displayName=` friendly display name
  - `readOnly=`
  - `hidden=`

## Important Discussions / Decisions
- Watermarks are content-level edits, not SharePoint display overlays.
- Users can manually remove watermarks by editing files, but there is no bulk undo feature now.
- Rewriting documents can affect document signatures because signatures depend on document content/package integrity.
- SharePoint metadata and permissions are not intentionally modified by the app; upload overwrites file content, not list metadata/ACLs.
- The customer may later need metadata-based routing and include/exclude folder scope.
- Recommended future design: external JSON rule config mapping metadata field/value + folder include/exclude to watermark PNG.
